## 1. 캠페인 도입의 전략적 함의

### 1.1 패러다임 전환: 자유 등록 --> 관리자 주도 캠페인

캠페인 도입 이전의 수요조사는 **상시 개방형 자유 등록** 모델이었다. 회원이 원할 때 자유 텍스트로 주제를 등록하고, 관심/참여 반응이 쌓이면 운영진이 개설을 검토하는 바텀업 방식이다.

캠페인 모델은 이를 **관리자 주도의 구조화된 수요 수집**으로 전환한다:

| 차원 | 자유 등록 (AS-IS) | 캠페인 기반 (TO-BE) |
|------|-------------------|---------------------|
| **수집 시점** | 상시 (학기 내내) | 기간 한정 (startDate~endDate) |
| **주제 범위** | 무제한 자유 텍스트 | 사전 정의 선택지 + 자유 입력 병행 |
| **수요 집중** | 분산 (유사 주제 난립) | 집중 (사전 주제로 수렴 유도) |
| **운영 리듬** | 비동기 (수시 확인) | 동기 (캠페인 기간 내 집중 운영) |
| **의사결정 근거** | 자유 텍스트 + 반응 수 | 구조화된 선호 + 주제별 정량 집계 |

### 1.2 트레이드오프 분석

#### 캠페인이 가져오는 이점

1. **수요 집중 효과**: 사전 주제 선택지가 "논문 읽기" / "논문 리딩" / "학술 논문 분석" 같은 유사 표현을 하나의 주제로 수렴시킨다. 제안서 1.4-(A)의 "자유서술 의존 → 수요 분산" 문제를 구조적으로 완화한다.

2. **집계 정확도 향상**: `campaignTopicId`로 수요를 주제별로 정확히 묶을 수 있다. 자유 텍스트 대비 집계 신뢰도가 높아진다. 히트맵, 주제별 응답률 등 정량 시각화의 기반이 된다.

3. **개설 전환 가속**: 기간 한정 → 수요가 한 시점에 집중 → 정족수(JOIN_THRESHOLD=3) 도달이 빨라진다. 운영진도 캠페인 종료 시점에 일괄 검토할 수 있어 reviewing 단계 정체가 줄어든다.

4. **운영 리듬 확립**: 학기 사이클에 맞춘 캠페인 운영이 가능해진다. "개강 2주 전 수요조사 → 개강 1주차 개설"이라는 예측 가능한 리듬이 생긴다.

5. **데이터 기반 기획**: 캠페인 단위로 응답률, 주제별 수요, 기간 내 등록 추이를 비교할 수 있어 다음 캠페인 기획의 정량 근거가 된다.

#### 캠페인이 초래할 수 있는 위험

1. **회원 자율성 침해**: 사전 주제에 없는 주제를 원하는 회원이 "내 수요는 여기 없는데"라는 좌절감을 느낄 수 있다. 특히 학회 특성상 연구 관심이 다양하므로 선택지가 좁으면 수요 누락이 발생한다.

2. **시간 제약 배제**: 캠페인 기간 외에 새로 가입한 회원이나 학기 중 새 관심이 생긴 회원이 수요를 등록할 수 없다. 기간 종료 후 등록 욕구가 사라지는 "수요 증발"이 일어날 수 있다.

3. **운영 부담 증가**: 캠페인 설정(주제 선정, 기간 설정, 상태 관리)이 추가 운영 업무가 된다. 소규모 운영진(현재 staff 규모 추정 3~5명)에게 부담이 될 수 있다.

4. **사전 주제 편향**: 운영진이 선정한 주제가 회원 실수요를 대표하지 못할 수 있다. 지난 학기 트렌드를 반영하되 새로운 관심사를 놓칠 위험이 있다.

### 1.3 균형 전략: 하이브리드 모델 (권고)

캠페인과 자유 등록을 **배타적 관계가 아닌 보완적 관계**로 설계한다.

```
현재 구현(useDemandCampaign.resolveCampaignPhase):
  - draft/none → isOpen=true, isVisible=false  (현행 자유 등록 유지)
  - active     → isOpen=true, isVisible=true   (캠페인 배너 + 등록 허용)
  - closed/ended → isOpen=false, isVisible=true (등록 폼 비활성)
```

**권고하는 하이브리드 설계**:

| 시나리오 | 등록 방식 | 근거 |
|----------|-----------|------|
| **캠페인 active 기간** | 사전 주제 칩 선택 + 자유 입력 병행 | 수렴 유도하되 표현력 보존 |
| **캠페인 미설정 (draft/none)** | 현행 자유 등록 그대로 | 하위 호환. 캠페인 미사용 학기도 안전 |
| **캠페인 ended 후** | 자유 등록 재개 (isOpen=true 복귀) 또는 "다음 캠페인까지 대기" 안내 | 운영 정책에 따라 선택 |

**핵심 원칙**: 캠페인은 "자유 등록을 대체"하는 것이 아니라 "구조화된 수집 창구를 추가"하는 것이다. 사전 주제를 선택하지 않고 자유 입력으로 등록하는 경로는 캠페인 active 기간에도 항상 열려 있어야 한다. 현재 코드에서 `DemandCampaignEditor`의 topics가 0개여도 저장 가능한 점이 이 원칙과 부합한다.

## 2. 캠페인 운영 플레이북

### 2.1 학기 사이클 연계 캠페인 타이밍

연세교육공학회의 운영 사이클(학기 기반)에 맞춘 캠페인 타이밍 모델:

```
[학기 종료 2주 전]              [방학]                    [개강]
     |                          |                          |
     v                          v                          v
 ┌──────────┐  ┌────────────────────────────┐  ┌───────────────────────┐
 │ 회고     │  │  캠페인 설계 (관리자)      │  │  개설 실행            │
 │ (retro)  │  │  - 지난 학기 미개설 이월   │  │  - 정족수 도달 주제   │
 │          │  │  - 신규 주제 후보 선정     │  │    reviewing → opened │
 │          │  │  - 기간/상태 설정          │  │  - 모임장 확보       │
 │          │  │                            │  │  - 설계 → 활동 생성  │
 └──────────┘  └────────────────────────────┘  └───────────────────────┘
                                |
                                v
                 ┌──────────────────────────────┐
                 │  수요 수집 (회원, 2~3주)     │
                 │  캠페인 active               │
                 │  - 사전 주제 칩 + 자유 입력  │
                 │  - 관심/참여 반응            │
                 └──────────────────────────────┘
```

#### 권장 타이밍 가이드

| 시점 | 활동 | 캠페인 상태 | 비고 |
|------|------|-------------|------|
| 학기 종료 2주 전 | DemandRetroSection으로 지난 학기 회고 | -- | 미개설 상위 주제 파악 |
| 방학 중~개강 3주 전 | 캠페인 설계 (주제·기간·설명) | `draft` | 콘솔에서 초안 작성 |
| 개강 2주 전 | 캠페인 오픈, 회원 안내 | `active` | 수요 수집 시작 |
| 개강 1주차 | 캠페인 마감 | `closed` | 집계·검토 시작 |
| 개강 2~3주차 | 정족수 주제 개설 | -- | StudyLaunchPanel 실행 |
| 학기 중반 | (선택) 2차 미니 캠페인 | `active` | 중간 수요 수집 |

**학기 중반 미니 캠페인**: 1학기에 1회만 진행하면 학기 중 새로 생긴 수요를 놓친다. 중간고사 후 2주간 "추가 스터디 수요조사"를 짧게 운영하면 수요 커버리지가 높아진다. 단, 운영 부담과 트레이드오프.

### 2.2 사전 주제 선택지 설계 원칙

사전 주제의 수와 구체성은 캠페인 효과를 좌우한다.

#### 적정 주제 수

| 주제 수 | 효과 | 위험 |
|---------|------|------|
| 3~5개 | 수요 강하게 수렴, 집계 명확 | 회원 선택지 부족 → 자유 입력 비율 과다 |
| **6~10개 (권장)** | 수렴과 다양성의 균형 | -- |
| 11~15개 | 세분화된 수요 포착 | 선택 피로, 각 주제당 응답 희석 |
| 16개+ | 거의 자유 등록과 동일 | 캠페인 의미 퇴색 |

#### 주제 설계 원칙

1. **MECE 지향 (상호배타·전체포괄)**: 교육공학 하위 분야(DOMAIN_OPTIONS: 교수설계, 학습분석, 에듀테크, HRD/평생교육, 교육평가, 연구방법론)를 축으로 주제를 분류하되, 분야 간 겹침을 최소화한다.

2. **추상도 조절**: "교수설계" (너무 넓음) < "ADDIE 모형 실습 스터디" (적절) < "ADDIE의 설계 단계에서 학습 목표 진술 방법" (너무 좁음). 회원이 "이 스터디에 참여하면 뭘 하는지" 상상할 수 있는 수준.

3. **지난 학기 회고 기반**: DemandRetroSection의 "미개설 상위 주제"를 다음 캠페인 주제 후보로 우선 반영. 이미 수요가 검증된 주제이므로 정족수 도달 가능성이 높다.

4. **트렌드 반영**: 학회 세미나 주제, 아카이브 인기 콘텐츠, 교육공학 학술 동향을 반영한 1~2개 신규 주제를 추가. "검증된 수요 + 탐색적 수요" 혼합.

5. **"기타/자유 제안" 슬롯 명시**: 사전 주제 목록 끝에 "이 외에 원하는 주제" 항목을 두어 목록에 없는 수요도 캡처. 이 슬롯의 응답이 많으면 다음 캠페인 주제 후보로 승격.

#### 주제 라벨 작성 가이드

```
좋은 예:
  "논문 읽기 방법론 스터디 (초급)"
  "생성형 AI 교육 활용 실습"
  "교육 데이터 분석 (R/Python)"

나쁜 예:
  "에듀테크"          → 너무 넓음, 무엇을 하는 스터디인지 불명확
  "Mayer의 멀티미디어 학습 이론 중 이중 부호화와 인지 부하의..."  → 너무 좁음
  "스터디"            → 의미 없음
```

### 2.3 수요조사 기간 설정 가이드

| 기간 | 적합 상황 | 주의점 |
|------|-----------|--------|
| 1주 | 미니 캠페인, 추가 수요 수집 | 응답률 낮을 수 있음 → D-day 긴급감으로 보완 |
| **2주 (권장)** | 메인 캠페인 | 충분한 노출 + 적절한 긴급감 |
| 3주 | 방학 중 (접속 빈도 낮을 때) | 초반 응답 후 후반 정체 가능 |
| 4주+ | 권장하지 않음 | 긴급감 부재 → "나중에 하지" 효과 |

**D-day 활용**: 현재 코드의 `CampaignState.daysLeft`를 회원 화면에 "D-7", "D-3" 배너로 노출하면 마감 임박 시 응답률이 급증하는 "데드라인 효과"를 활용할 수 있다. 마지막 3일의 응답이 전체의 40~50%를 차지하는 것이 일반적이므로, 2주 기간 중 D-3 시점에 리마인더 알림을 추가하면 효과적이다.

## 3. 제안서 Phase 2~4 구체화 + 캠페인 연계 재정렬

### 3.1 캠페인 도입이 기존 Phase에 미치는 영향

캠페인이 생기면서 제안서의 일부 항목은 **이미 해결되거나 우선순위가 변경**된다.

#### 해결/완화된 항목

| 제안서 항목 | 캠페인으로 해결되는 정도 | 잔여 과제 |
|-------------|--------------------------|-----------|
| **2.1.1 구조화 필드 (domain)** | 부분 해결. 캠페인 topic에 domain을 사전 매핑하면 `demandPref.domain` 자동 채움 | difficulty, preferredTime 은 캠페인과 별개로 필요 |
| **2.1.2 유사 수요 안내** | 대폭 완화. 사전 주제 선택이 유사 표현 분산을 방지 | 자유 입력 경로에는 여전히 필요 |
| **2.3.1 유사 수요 클러스터링** | 우선순위 하락. 캠페인 topicId로 묶이므로 수동 클러스터링 필요성 감소 | 자유 입력 수요끼리의 클러스터링은 여전히 유용 |
| **2.6.3 학기 전환 이월** | 운영 프로세스로 대체. 캠페인 설계 시 지난 학기 미개설 상위를 주제로 반영 | 자동 이월 기능은 Phase 4 유지 |

#### 우선순위가 올라간 항목

| 제안서 항목 | 이유 |
|-------------|------|
| **2.4.1 자동 단계 전환** | 캠페인 종료와 동시에 정족수 달성 수요를 일괄 reviewing 전환하면 운영 효율이 극대화 |
| **2.6.1 정족수 도달 알림** | 캠페인 기간 내 실시간 알림이 있어야 운영진이 종료 전에 대응 가능 |
| **2.2.1 주제별 수요 히트맵** | 캠페인 topicId 기반 집계가 가능해져 히트맵 구현이 실질적으로 의미를 가짐 |
| **2.4.2 퍼널 지표 강화** | 캠페인 단위 퍼널(캠페인 시작 → 수요 등록 → 정족수 → 개설)이 새 분석 축 |

### 3.2 재정렬된 Phase 로드맵

#### Phase 1: Quick Win (1~2주) -- 변경 없음, 즉시 효과

원안 Q1~Q5 유지. 캠페인과 무관하게 기존 자유 등록 흐름을 개선한다.

추가 권고:
- **Q6 (신규)**: 캠페인 active 시 DemandSurveySection에 캠페인 배너 + 사전 주제 칩 렌더링. 칩 클릭 시 body 프리필 + `demandPref.campaignTopicId` 자동 저장. 이미 타입에 `campaignTopicId` 필드가 존재하므로 UI 연결만 필요.

#### Phase 2: 구조화 및 집계 (3~4주) -- 캠페인 연계 재설계

| # | 항목 | 캠페인 연계 변경 | 노력 |
|---|------|------------------|------|
| M1 | 구조화 필드 | domain은 캠페인 topic에서 자동 채움. difficulty/preferredTime은 독립 유지 | MED (축소) |
| M2 | 주제별 수요 히트맵 | **캠페인 topicId별 집계를 1차 축으로**, 자유 입력은 "미분류"로. domain x difficulty 매트릭스는 2차 | MED |
| M3 | 시간대 겹침 분석 | 변경 없음 (캠페인과 직교) | MED |
| M4 | "내 수요" 추적 뷰 | 캠페인 이름·기간을 수요 카드에 표시 | MED |
| M5 | 설계 템플릿 | 변경 없음 | LOW-MED |
| M6 | 정족수 도달 알림 | **캠페인 종료 48시간 전 미도달 수요 리마인더 추가** | LOW-MED |
| **M7 (신규)** | **캠페인 결과 대시보드** | 캠페인 종료 후 요약: 응답률, 주제별 분포, 기간 내 일별 등록 추이 | MED |

#### Phase 3: 매칭 및 퍼널 (5~6주) -- 캠페인 단위 퍼널

| # | 항목 | 캠페인 연계 변경 | 노력 |
|---|------|------------------|------|
| H1 | 유사 수요 클러스터링 | **우선순위 하락**. 캠페인 topicId가 1차 클러스터 역할. 자유 입력 수요에 대해서만 수동 클러스터링 | MED (축소) |
| H2 | 모임장 추천 | 캠페인 topicId별 모임장 후보 제안 (해당 분야 경험자 필터) | MED-HIGH |
| H3 | 퍼널 지표 강화 | **캠페인 단위 퍼널** 추가: 캠페인 노출 → 등록 → 정족수 → 개설 | HIGH |
| H4 | 학기 간 트렌드 | **캠페인 간 비교** 추가: 동일 주제의 학기별 수요 변화 | MED |
| H5 | 수요 댓글/토론 | 변경 없음 | MED |

#### Phase 4: 자동화 및 예측 (7~8주+) -- 캠페인 자동화

| # | 항목 | 캠페인 연계 변경 | 노력 |
|---|------|------------------|------|
| L1 | 미처리 수요 리마인더 | **캠페인 종료 후 미검토 수요** 자동 리마인더 (종료 후 7일 내 검토 미완 → 알림) | MED |
| L2 | 학기 전환 이월 | 캠페인 설계 시 지난 학기 미개설 상위 자동 추천 (DemandRetroSection → CampaignEditor 연동) | MED |
| L3 | 알림 체계 확장 | 캠페인 오픈/마감 임박/결과 알림 추가 | HIGH |
| L4 | 수요 기반 콘텐츠 제안 | 캠페인 topicId별 관련 아카이브/러닝가이드 자동 연결 | MED-HIGH |
| **L5 (신규)** | **캠페인 템플릿** | 지난 학기 캠페인을 복제하여 다음 학기 초안으로. 주제 이월 + 기간 자동 조정 | LOW-MED |
| **L6 (신규)** | **캠페인 일괄 전환** | 캠페인 종료 시 정족수 달성 수요를 일괄 reviewing 전환 + 운영진 알림 | MED |

## 4. 캠페인 단위 데이터 및 KPI 재설계

### 4.1 캠페인 단위 핵심 KPI

| KPI | 정의 | 측정 방법 | 목표 기준 |
|-----|------|-----------|-----------|
| **캠페인 응답률** | 캠페인 기간 내 수요 등록 수 / 활성 회원 수 | 캠페인 종료 시 집계. 활성 회원은 최근 30일 로그인 기준 | 30% 이상 |
| **주제 집중도** | 사전 주제 선택 등록 / 전체 등록 (자유 입력 포함) | `campaignTopicId` 보유 비율 | 60~80% (너무 높으면 주제 편향 의심) |
| **주제별 응답률** | 각 사전 주제의 등록 수 / 전체 등록 수 | topicId별 count | 균등 분포 지향, 편중 시 주제 재설계 |
| **기간 내 등록 추이** | 일별 등록 건수 (캠페인 시작~종료) | createdAt 기준 일별 집계 | D-3 이후 급증 패턴 확인 |
| **캠페인 -> 개설 전환율** | 캠페인 내 등록 수요 중 opened 비율 | 캠페인 연동 수요의 status 집계 | 40% 이상 |
| **정족수 도달률** | 캠페인 종료 시 JOIN_THRESHOLD(3) 이상 수요 비율 | joinCounts >= 3 / 전체 수요 | 50% 이상 |
| **D-day 효과 계수** | 마지막 3일 등록 비율 / 전체 기간 등록 비율 | 일별 등록 분포 분석 | 모니터링용 (최적 기간 설정 근거) |

### 4.2 캠페인 간 비교 지표

다수 캠페인이 누적되면 캠페인 간 비교가 운영 개선의 핵심 데이터가 된다.

| 비교 축 | 지표 | 활용 |
|---------|------|------|
| **학기 간** | 동일 주제 수요 변화 | 트렌드 파악 (관심 상승/하강) |
| **캠페인 기간 간** | 2주 vs 3주 캠페인의 응답률 비교 | 최적 기간 발견 |
| **주제 수 간** | 6개 vs 10개 주제 캠페인의 주제 집중도 비교 | 최적 주제 수 발견 |
| **시기 간** | 방학 중 vs 학기 중 캠페인 응답률 | 최적 시기 발견 |

### 4.3 기존 제안서 KPI와의 통합

기존 제안서(4절)의 KPI를 캠페인 단위로 재해석한다:

| 기존 KPI | 캠페인 맥락 재해석 | 측정 변경점 |
|----------|-------------------|-------------|
| 수요 -> 개설 전환율 | **캠페인당** 전환율 (캠페인 없는 자유 수요와 분리 집계) | `campaignTopicId` 유무로 분리 |
| 개설 리드타임 | 캠페인 종료일 → opened 까지 일수 (캠페인이 기준점 제공) | 캠페인 endDate를 기산점으로 |
| 수요당 평균 참여 의사 | 사전 주제별 vs 자유 입력별 참여 의사 비교 | topicId별 joinCount 평균 |
| 개설 후 실참여율 | 변경 없음 (conversionData 그대로) | -- |
| 수요 중복률 | 캠페인에서는 의미 축소 (사전 주제가 중복 방지). 자유 입력에 대해서만 계산 | `campaignTopicId` 부재 수요만 대상 |

### 4.4 데이터 저장 설계 고려

현재 캠페인은 `site_settings` 테이블에 JSON 문자열로 저장된다(`demand_campaign:{semester}`). 이 구조에서의 데이터 한계와 확장 방안:

| 현재 구조 | 한계 | 확장 방안 |
|-----------|------|-----------|
| 학기당 1개 캠페인 | 학기 중 미니 캠페인 추가 불가 | 키를 `demand_campaign:{semester}:{seq}`로 확장하거나, topics 배열 내에 "라운드" 구분 추가 |
| 캠페인 결과 미저장 | 캠페인 종료 시 집계 결과가 별도 저장되지 않음 | 캠페인 closed 전환 시 스냅샷을 `campaignResult` 필드로 저장 |
| 주제별 수요 연결 | `CommQuestion.demandPref.campaignTopicId`로 연결 | 충분. 추가 구조 불필요 |

## 5. 리스크 및 엣지케이스

### 5.1 캠페인 미설정 시 폴백

**시나리오**: 운영진이 학기가 시작되어도 캠페인을 설정하지 않았다.

**현재 동작** (`resolveCampaignPhase`):
- `campaign === null` 또는 `status === "draft"` → `{ phase: "none", isOpen: true, isVisible: false }`
- 회원 화면은 **현행 자유 등록 그대로** 작동한다. 캠페인 배너 미노출.

**평가**: 안전한 폴백이다. 캠페인이 없으면 기존과 동일하게 작동하므로 운영 누락에 의한 서비스 중단이 없다. 다만 "캠페인 미설정" 상태가 의도인지 누락인지 운영진이 인지하기 어려우므로, 콘솔 대시보드에 "이번 학기 캠페인 미설정" 알림을 추가하는 것이 바람직하다.

### 5.2 캠페인 기간 종료 후 수요 처리

**시나리오**: 캠페인이 ended 상태인데 회원이 수요를 등록하고 싶다.

**현재 동작**: `isOpen: false` → 등록 폼 비활성화.

**권고 처리 방안**:

| 옵션 | 설명 | 장단점 |
|------|------|--------|
| A. 폼 비활성 + 안내 메시지 | "이번 캠페인이 마감되었습니다. 다음 캠페인을 기다려주세요." | 명확하지만 수요 유실 |
| **B. 자유 입력 재개 (권고)** | 캠페인 ended 후에도 자유 입력은 허용. 단, 캠페인 주제 칩은 숨김 | 수요 유실 방지 + 구조/비구조 분리 |
| C. "대기 수요" 별도 수집 | 캠페인 외 수요를 "대기" 태그로 분류. 다음 캠페인 설계 시 참고 | 구현 복잡 |

**권고**: 옵션 B. `resolveCampaignPhase`의 ended 상태에서 `isOpen`을 조건부로 true로 변경하되, 캠페인 주제 칩은 숨기고 자유 입력만 허용. 이렇게 하면 캠페인 밖 수요도 캡처하면서, 캠페인 내 구조화 수요와 구분된다(`campaignTopicId` 부재로 식별).

### 5.3 복수 캠페인 동시 진행

**시나리오**: 같은 학기에 "1차 수요조사 (개강 전)" + "2차 미니 수요조사 (중간고사 후)"를 운영하고 싶다.

**현재 한계**: `site_settings` 키가 `demand_campaign:{semester}`로 학기당 1개로 고정된다. 2차 캠페인을 설정하면 1차를 덮어쓴다.

**단기 우회**: 1차 캠페인을 `closed`로 전환 후 2차 캠페인 내용으로 덮어쓰기. 1차 결과는 이미 `CommQuestion.demandPref.campaignTopicId`에 기록되어 있으므로 수요 데이터는 유실되지 않는다. 단, 캠페인 메타(제목·주제 목록·기간)의 1차 이력이 사라진다.

**장기 해결 (Phase 4+)**:
- 키를 `demand_campaign:{semester}:{round}` (예: `demand_campaign:2026-2:1`, `demand_campaign:2026-2:2`)로 확장.
- 또는 `DemandCampaign`에 `round: number` 필드를 추가하고, 같은 학기에 여러 캠페인을 배열로 저장.
- `CampaignState` 판정 시 가장 최근 active 캠페인을 기준으로.

### 5.4 캠페인 외 자유 수요 처리

**시나리오**: 캠페인이 active인데 회원이 사전 주제를 선택하지 않고 자유 텍스트로만 등록했다.

**현재 동작**: `demandPref.campaignTopicId`가 없는 상태로 저장된다. 기능적으로 문제 없다.

**운영 관점 과제**:
- 집계 시 캠페인 주제별 통계에 자유 입력 수요가 빠진다 → "미분류" 카테고리로 별도 집계.
- 자유 입력 수요 비율이 높으면(>40%) 사전 주제 설계가 회원 수요를 충분히 반영하지 못했다는 신호 → 다음 캠페인 주제 재설계 근거.
- 자유 입력 수요 중 반복 등장하는 키워드를 추출하여 다음 캠페인 주제 후보로 제안하는 기능 검토 (Phase 4).

### 5.5 캠페인 상태 전환 실수

**시나리오**: 운영진이 실수로 draft → active를 너무 일찍 전환했거나, 의도치 않게 closed로 전환했다.

**현재 안전장치**: 없음. 상태 전환은 저장 버튼 1회로 즉시 반영된다.

**권고 안전장치**:
1. active → closed 전환 시 확인 다이얼로그: "마감하면 회원 등록이 중단됩니다. 마감하시겠습니까?"
2. closed → active 재활성화 허용 (실수 복구 경로).
3. 캠페인 변경 이력 로깅: `updatedBy`, `updatedAt`은 이미 존재하므로, 상태 변경 시 별도 히스토리 배열 추가를 검토 (statusHistory 패턴, 제안서 2.4.2와 동일).

### 5.6 데이터 정합성 리스크

| 리스크 | 상세 | 완화 |
|--------|------|------|
| topicId 불일치 | 캠페인 주제를 삭제/변경한 후 이미 해당 topicId로 등록된 수요와 불일치 | 캠페인 active 이후 주제 삭제 방지 (UI 경고) 또는 soft delete |
| 학기 키 불일치 | 캠페인의 semester와 보드의 contextId(demand-{semester})가 다른 학기 키를 참조 | `useEffectiveSemesterKey`로 통일 (현재 코드가 이미 이 패턴) |
| 동시 편집 | 두 운영진이 동시에 캠페인을 편집하면 후발 저장이 선발을 덮어씀 | `updatedAt` 기반 낙관적 잠금 또는 최소한 "다른 사람이 N분 전에 수정했습니다" 경고 |

### 5.7 확장성 리스크

| 리스크 | 규모 기준 | 완화 |
|--------|-----------|------|
| 주제 수 증가에 따른 UI 과밀 | 15개+ 주제 시 칩 UI 스크롤 필요 | 카테고리별 아코디언 또는 검색 가능한 드롭다운으로 전환 |
| 캠페인 히스토리 증가 | 10+ 학기 누적 시 site_settings 단일 레코드 크기 | JSON 크기는 캠페인당 2~5KB 수준으로 문제 없음. 학기별 별도 레코드이므로 누적도 선형 |
| 수요 건수 증가 | 100+ 수요/학기 시 목록 렌더 성능 | 현재 commQuestionsApi.listByBoard가 전건 로드. 페이지네이션 또는 가상 스크롤 검토 |

## 6. 실행 우선순위 요약

캠페인 전략을 반영한 전체 우선순위를 재정리한다.

### 즉시 (캠페인 구현과 동시)

1. **캠페인 배너 + 주제 칩 연동** (Q6): DemandSurveySection에서 campaign.status === "active" 시 배너·칩·D-day 렌더. 칩 선택 시 campaignTopicId 저장.
2. **캠페인 ended 후 자유 등록 재개** (5.2 옵션 B): isOpen 조건 조정.
3. **active 상태에서 주제 삭제 방지** (5.6): UI 경고.

### 단기 (Phase 1~2, 1~4주)

4. 기존 Q1~Q5 (유사 수요 안내, 정족수 자동 전환, 수요 편집, 관심 알림, 괴리 지표)
5. **캠페인 결과 대시보드** (M7): 캠페인 종료 후 topicId별 집계·일별 추이.
6. **캠페인 종료 미도달 리마인더** (M6 확장): 종료 48시간 전 + 종료 후 7일 미검토 알림.

### 중기 (Phase 2~3, 3~6주)

7. 구조화 필드 완성 (M1 축소판: difficulty, preferredTime)
8. 캠페인 topicId 기반 히트맵 (M2)
9. 캠페인 단위 퍼널 (H3)
10. 캠페인 간 비교·트렌드 (H4)

### 장기 (Phase 4+, 7주+)

11. 복수 캠페인 지원 (5.3)
12. 캠페인 템플릿 복제 (L5)
13. 캠페인 종료 시 일괄 reviewing 전환 (L6)
14. 자유 입력 키워드 추출 → 다음 캠페인 주제 추천

## 부록: 의사결정 기록 (ADR)

### ADR-1: 캠페인과 자유 등록의 관계

- **결정**: 하이브리드 모델 — 캠페인은 자유 등록을 대체하지 않고 보완한다.
- **근거**: 학회 구성원의 연구 관심이 다양하여 사전 주제만으로는 수요를 완전히 포괄할 수 없다. 자유 입력 경로를 유지해야 수요 누락을 방지하고, 자유 입력 비율 자체가 주제 설계 품질의 피드백 지표가 된다.
- **대안**: (a) 캠페인 기간에는 자유 입력 차단 → 기각 (수요 유실 위험). (b) 캠페인 없이 구조화 필드만 추가 → 기각 (집중 수집·학기 리듬 확보 불가).
- **결과**: 캠페인 topicId 유무로 구조화/비구조화 수요를 분리 집계. 자유 입력 비율 > 40%이면 주제 재설계 신호.

### ADR-2: 캠페인 저장 구조

- **결정**: site_settings 재사용 (학기별 단일 레코드, JSON).
- **근거**: 별도 컬렉션 생성 없이 기존 인프라 활용. 캠페인 데이터 크기가 작고(2~5KB/학기), 학기당 1개 캠페인이 초기 운영에 충분하다.
- **대안**: (a) demand_campaigns 별도 컬렉션 → 기각 (오버엔지니어링, Firestore rules 변경 필요). (b) DemandCampaign을 comm_boards에 중첩 → 기각 (관심사 혼합).
- **결과**: 복수 캠페인 지원이 필요해지면 키 구조 확장(`{semester}:{round}`)으로 대응. 마이그레이션 비용 낮음.

### ADR-3: 캠페인 종료 후 등록 정책

- **결정**: 캠페인 ended 후 자유 입력 재개 권고.
- **근거**: 캠페인 종료 후에도 수요가 발생할 수 있으며, 이를 차단하면 수요 증발이 일어난다. 자유 입력 수요는 campaignTopicId 부재로 캠페인 수요와 자연스럽게 분리된다.
- **대안**: (a) 완전 차단 → 기각 (수요 유실). (b) "대기 수요" 별도 태그 → 과도한 복잡도.
- **결과**: 운영진은 캠페인 외 자유 수요를 별도 탭/필터로 확인. 다음 캠페인 주제 후보로 활용.
