## 2. 진단 — IA 약점 6가지

### 2-1. 그룹 라벨 모호성 — 경계 불명확

**"학사" vs "활동" 경계 붕괴**

- 학사 그룹에: `학술활동 대시보드`, `신청 승인 대시보드` — 이름에 '활동'이 들어간 항목이 학사에 있음
- 활동 그룹에: `논문 심사 연습`, `심사 질문 템플릿` — 학위 과정 흐름인데 활동에 있음
- 연구 키워드가 `연구활동`(학사) + `연구방법 가이드`(아카이브) + `연구변인`(아카이브)로 3군데 분산

**"회원/문의" 강제 결합**

슬래시 라벨이 두 개의 독립적 업무 흐름을 억지로 합침. 회원 관리(승인·연락망)와 소통 채널(문의·피드백)은 사용 빈도와 담당자가 다를 수 있음.

**"아카이브" 목적 모호**

지식 저장소인지 콘텐츠 관리 도구인지 불명확. `콘텐츠 갭`은 운영 분석 도구인데 학술 자료 허브 그룹에 포함돼 있음.

---

### 2-2. 과밀 그룹 — 회원/문의 (11개)

11개 항목 중 성격을 분류하면:

| 성격 | 항목 | 비고 |
|---|---|---|
| 핵심 일상 업무 | 회원관리, 잠재회원, 연락망, 문의 답변, 피드백, 운영진 설정 | 주 1회 이상 접근 |
| 신규 회원 처리 | 신규 회원 체크리스트 (온보딩 그룹) | 입학 시즌 집중 |
| 마이그레이션·검증 도구 | 회원 검증, 포트폴리오 검증, 졸업논문 매핑, 신청자 학번 연동, 교사 affiliation 분리 | 일회성·프로젝트성 |

마이그레이션 도구 5개가 일상 업무 항목과 동등한 위치에 나열되어 **인지 잡음**을 유발. Miller의 7±2 법칙(그룹당 5~9개)을 초과.

---

### 2-3. 과소 그룹 — 온보딩 (1개)

신규 회원 체크리스트 하나를 위해 그룹 계층을 소비. 아코디언 접기 버튼 클릭→항목 1개 — 불필요한 인터랙션 비용. "사람" 관리 흐름의 하위 항목으로 통합이 적절.

---

### 2-4. AI 관심사 분산 — 2개 그룹에 5개 항목

| 현재 그룹 | AI 관련 항목 |
|---|---|
| 모니터링 | AI 포럼 운영 |
| 시스템 (presidentOnly) | 챗봇 설정, AI 에이전트 관리, 에이전트 워크플로우, 에이전트 작업 보드 |

5개 항목이 2개 그룹에 분산. AI 도구는 향후 확장 예정이므로 독립 그룹이 필요. 현재 `AI 포럼 운영`은 presidentOnly가 아닌데 `챗봇 설정`은 presidentOnly — 권한 정책 기준도 불일치.

---

### 2-5. 인사이트 위치 부적절

`인사이트`는 사용 분포·참여 현황 등 운영 대시보드 성격인데 `모니터링` 그룹에 있음. `Cron 실행 이력`, `감사로그` 같은 시스템 기술 로그와 같은 그룹에 놓여 발견성이 낮음. 운영진은 홈 → 인사이트 흐름을 기대하지 모니터링 그룹을 열어 인사이트를 찾지 않음.

---

### 2-6. 모바일 탭바 — 실질적 사용 불가

현재 구현: `visibleGroups.flatMap()` 으로 전체 항목을 수평 탭으로 flat하게 나열.  
→ 51개 항목 × 텍스트 탭 = 가로 스크롤 수 미터.  
→ 그룹 구분자(`|`)가 시각적 분리를 제공하지만 모바일에서 메뉴를 탐색하는 패턴 자체가 깨짐.  
→ 운영콘솔이 모바일 1차 사용 환경은 아니지만, 현장(학회 행사장 등)에서의 빠른 접근이 불가능.

## 3. 재그룹핑 제안

### 3-1. 설계 원칙

1. **Objects-based IA**: 관리 대상(사람/콘텐츠/활동)을 최상위 기준 — 태스크 기반보다 전환 비용이 낮음
2. **사용 빈도 기반 배치**: 일상 업무 항목 상단, 드문 관리 도구 하단 접기
3. **단일 관심사 그룹**: 그룹 하나 = 담당자가 같고 사용 타이밍이 비슷한 항목들
4. **AI 통합**: 분산된 AI 관련 5개를 단일 그룹으로 집합
5. **그룹 수 유지 또는 소폭 조정**: 9 → 8 (급격한 변화 없음)

### 3-4. 제안 구조 상세

#### 홈 (항상 펼침 — non-collapsible)
```
홈               ← 운영 대시보드
업무노트         ← 핸드오버 노트
인사이트         ← 사용 분석 (현재: 모니터링 → 홈으로)
```
> 세 항목은 접기 없이 항상 노출. 운영진이 세션 시작 시 가장 먼저 확인하는 항목.

```

> 제안: `AI 포럼 운영` + `에이전트 작업 보드`는 adminOrAbove, 나머지 3개는 presidentOnly 유지.

#### 시스템 (presidentOnly)
```
사이트 설정
학사 일정
실험실
감사로그         ← (현재: 모니터링)
Cron 실행 이력   ← (현재: 모니터링)
```

## 4. 네이밍 가이드

### 4-1. 그룹 라벨 원칙

| 원칙 | 설명 |
|---|---|
| 명사 중심 | 동사 없음. "관리"를 그룹명에 붙이지 않음 |
| 2단어 이하 | "·" 연결 허용, 슬래시 금지 |
| 운영진 어휘 | 시스템 내부 용어 지양 (예: "학술활동 대시보드" → "학술 활동 현황") |
| 영문 최소화 | AI & 자동화는 브랜드 용어로 예외 허용 |

### 4-2. 항목 라벨 수정 제안

| 현재 라벨 | 제안 라벨 | 수정 이유 |
|---|---|---|
| 교사 affiliation 분리 | 교사 소속 분리 | 한국어 통일 |
| 활동 이력 (전공대표·조교·학회) | 활동 이력 | 괄호 제거 — 상세는 아이콘 tooltip으로 |
| 신청 승인 대시보드 | 활동 신청 승인 | "대시보드" 제거, 행위 중심 네이밍 |
| 학술활동 대시보드 | 학술 활동 현황 | "대시보드" 제거, 상태 중심 네이밍 |
| Cron 실행 이력 | Cron 이력 | 압축 (사이드바 공간 제약) |
| 에이전트 작업 보드 | 에이전트 보드 | 압축 |

> **변경 금지**: `인지디딤판` — 고유 브랜드 용어, 그대로 유지

### 4-3. 2단계 계층 (서브그룹) 검토

현 아코디언 구조에서 **그룹 내 "관리 도구" 접기 섹션**이 유일하게 권장하는 2단계 계층.  
전체 메뉴를 2단계 트리로 전환하는 것은 현재 규모(51항목)에서 오버엔지니어링. "활동 운영" 9개가 최다 그룹이 되는 구조이므로 2단계 없이도 허용 범위.

## 5. 인터랙션 개선

### 5-1. 홈 그룹 항상 펼침

현재: 홈 그룹도 아코디언으로 접기 가능  
제안: `홈` 그룹은 `<button>` 토글 없이 항상 펼침 (non-collapsible)  
구현: `SidebarGroup`에 `alwaysOpen?: boolean` prop 추가 → 버튼 제거, open 상태 고정 true

---

### 5-2. 관리 도구 접기 서브섹션

"사람" 그룹 내 마이그레이션 5개, "아카이브" 그룹 내 콘텐츠 갭을 서브섹션으로 분리.

```
[펼치기/접기] 관리 도구  ← 파선 border + muted 배경
  ├ 회원 검증
  ├ 포트폴리오 검증
  ...
```

UX 규칙:
- 기본: 접힘 (collapsed)
- URL이 서브섹션 항목 중 하나와 일치하면 자동 펼침
- 서브섹션 열림 시 그룹 전체 아코디언도 자동 열림 (현재 동작 유지)

---

### 5-3. 검수 배너 위치 및 스타일

현재: 사이드바 최상단 독립 배너, 아코디언 (클릭해야 항목 목록 표시)  
문제: 상단에 있어 전체 메뉴 시작점을 가림. 접기/펼치기 클릭 비용.

제안:
- 배너를 "홈" 그룹 바로 아래로 이동
- 접기 없이 건수가 있는 항목을 직접 링크로 나열 (최대 5개, `total > 0`일 때만 표시)
- 총 건수가 많아지면 가장 급한 것부터 표시 (우선순위: 회원 승인 > 미답변 문의 > 피드백 > 아카이브 > 초안)
- 모바일: 페이지 상단 `<div className="sticky top-0">` 바에 총 N건만 뱃지로 표시

```
홈 그룹 (항상 펼침)
  홈
  업무노트
  인사이트

처리 대기 배너 (total > 0일 때만)
  ├ 회원 승인 대기 3건 →
  ├ 미답변 문의 1건 →
  └ 콘텐츠 초안 2건 →

사람 그룹 (아코디언)
  ...
```

### 5-4. 빠른 접근 — 사이드바 검색 (선택적)

51개 항목이 넘으면 항목 이름을 기억 못하는 경우 발생. 특히 신규 운영진.

제안: 사이드바 상단 `<input placeholder="메뉴 검색…" />` — client-side 필터링 (Firestore 불필요)

```
[🔍 메뉴 검색…   ]
```

동작:
- 타이핑 시 라벨에 키워드 포함된 항목만 표시 (그룹 계층 유지, 빈 그룹 숨김)
- Escape로 초기화
- 검색 중에는 아코디언 상태와 무관하게 모든 매칭 항목 표시

구현 난도: layout.tsx의 `visibleGroups`를 `useMemo`로 필터링, `useState<string>` 검색어 관리. 약 40줄 추가.

### 5-6. 모바일 개편 — Drawer 방식

현재: 전 항목 수평 탭바 flat 나열 (사용 불가 수준)

제안: **Drawer(Slide-over) 방식**

```
[운영콘솔]                     [☰]
───────────────────────────────────

대안 (Bottom Nav, 옵션 B):

- "더보기"에서 나머지 5개 그룹 표시
- 구현 부담 높고 "더보기" 패턴이 항목 발견성을 가림 → 비권장

## 6. 단계적 롤아웃

큰 개편을 한 번에 배포하면 운영진 혼선. 4단계로 분리.

### Phase 1 — 라벨 수정 (1일, 리스크 최소)

변경 범위: `layout.tsx`의 `label` 문자열만

```
회원/문의        → 사람
학사             → 학사·성장
활동             → 활동 운영
(시스템 내부에서) → AI & 자동화 (새 그룹 라벨로 준비)
```

항목 라벨:
```
"교사 affiliation 분리"    → "교사 소속 분리"
"신청 승인 대시보드"       → "활동 신청 승인"
"학술활동 대시보드"        → "학술 활동 현황"
"활동 이력 (전공대표·조교·학회)" → "활동 이력"
```

검증: 운영진 슬랙에 스크린샷 공유, 1~2일 피드백 수렴.

### Phase 2 — 항목 재배치 (3~4일)

그룹 간 항목 이동 (href 변경 없음, NAV_GROUPS 배열 재편):

1. `온보딩` 그룹 해체 → `신규 회원 체크리스트` → `사람` 그룹 하단
2. `인사이트` → `모니터링` 에서 `홈` 그룹으로
3. `신청 승인 대시보드`, `학술 활동 현황` → `학사·성장` 에서 `활동 운영`으로
4. `논문 심사 연습`, `심사 질문 템플릿` → `활동`에서 `학사·성장`으로
5. `AI 포럼 운영` → `모니터링`에서 `AI & 자동화`(신설)로
6. `챗봇 설정`, `AI 에이전트 관리`, `에이전트 워크플로우`, `에이전트 작업 보드` → `시스템`에서 `AI & 자동화`로
7. `감사로그`, `Cron 이력` → `모니터링`에서 `시스템`으로 → `모니터링` 그룹 자연 소멸

## 7. 개편 근거 및 참고

### 7-1. IA 원칙

| 원칙 | 적용 |
|---|---|
| **Objects-based IA** | 관리 대상(사람/콘텐츠/활동/지식)을 최상위 기준으로 |
| **Miller의 7±2** | 그룹당 5~9개 일반 항목 목표 — 마이그레이션 도구 접기로 달성 |
| **Progressive Disclosure** | 일상 업무 노출 → 관리 도구 접기 → 시스템/AI는 하단 |
| **Fitts의 법칙** | 고빈도 항목(홈·회원관리·문의)을 최단 거리에 |
| **인지 일관성** | AI 관련 항목을 단일 그룹으로 수렴 |

### 7-2. 도메인 특이점

운영진의 핵심 일상 업무 4가지 — 이 4가지가 최단 거리에 있어야 함:

1. **회원 승인** — 배지 배너 + `사람 > 회원관리`
2. **문의 답변** — 배지 + `사람 > 문의 답변`
3. **활동 관리** — `활동 운영`
4. **콘텐츠 발행** — `콘텐츠`

마이그레이션 도구(학번연동, affiliation분리, 졸업논문매핑)는 프로젝트성 — 학기 또는 연 1회 사용 → 항상 노출 불필요.

AI & 자동화 5개는 현재 성장 중인 기능 영역 → 독립 그룹으로 분리해 향후 항목 추가 시 그룹 팽창 관리 가능.

### 7-3. 미결 결정사항 (개발자/운영자 판단 필요)

| 항목 | 선택지 | 권장 |
|---|---|---|
| `학사 일정` 위치 | 시스템 유지 vs 학사·성장으로 이동 | 학사·성장 이동 (학사 일정은 학사 행정) |
| `AI 포럼 운영` 권한 | presidentOnly vs adminOrAbove | adminOrAbove (포럼은 관리자도 모니터링 필요) |
| 모바일 방식 | Drawer vs Bottom Nav | Drawer (구현 단순, 기존 컴포넌트 재사용) |
| Phase 4 타이밍 | 즉시 vs 별도 스프린트 | 별도 스프린트 (사용 패턴 데이터 먼저 수집) |
